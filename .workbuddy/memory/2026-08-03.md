# 2026-08-03 工作日志

## 文本对比首次打开延迟/概率无结果优化
用户反馈：第一次进入文本对比界面时概率不出结果，要等很久才出现。

### 根因排查
1. **"无结果"并非 diff 算法问题**：排查发现 `onDidUpdateDiff` 正常触发、`getLineChanges()` 在 Monaco 0.53 返回的变更行数正确。
2. **worker 预热路径错误才是真问题**：`js/loader.js` 的 `prewarmWorker()` 硬编码请求 `monacoBase/base/worker/workerMain.js`；但当前使用的 monaco-editor 0.53.0（阿里云/淘宝镜像）min 产物已改为**扁平化 + 内容哈希**，worker 文件实际名为 `workers.<hash>.js`，旧路径会**404**。虽然 `prewarmWorker()` 失败被静默吞掉，但启动阶段少了一次把 worker 脚本拉进缓存/真正起 worker 的机会。
3. **首次点开对比时 Monaco 才创建 worker**：worker 脚本未预热 + CDN 抖动，导致用户第一次进对比时才现场下载/创建 worker，出现长时间空白或"概率不出结果"。

### 改动
- `js/loader.js` `prewarmWorker()` 改为**版本无关预热**：
  - 新版 Monaco（提供 `MonacoEnvironment.getWorker`）→ 直接调用 Monaco 自带的 worker 工厂创建一个一次性 worker，让 Monaco 自己解析正确的哈希 worker 路径，起成功后再 `terminate()`；不再硬猜文件名。
  - 旧版 Monaco 没有 `getWorker` → 回退到原来的 `base/worker/workerMain.js` 预取。
- `js/app.js` 已接入的 `prewarmDiff()` 在启动空闲期跑微型 diff，提前创建并预热实际 diff 编辑器；
  - 新增 `clearWarmPlaceholder()` 防止预热占位文本泄漏到用户视图；
  - `openDiff()` 默认填充改为 `skipDefaults` 模式，调用方自己用 `batchDiffUpdate` 一次性替换两侧内容，避免重复计算；
  - `batchDiffUpdate()` 先 `setModel(null)` 再改两侧，再挂模型，只算一次；
  - `syncDiffModel()` 加 `beginDiffCompute()`/`endDiffCompute()` 加载遮罩 + 12s 超时自救（重试按钮）；
  - `updateDiffOverview()` 用签名缓存 + rAF 节流 + 事件委托，避免每次滚动都重建 DOM。
- `index.html` 增加 `<div id="diffLoading" class="diff-loading" hidden>`。
- `css/diff.css` 增加 `.diff-loading`、`.diff-loading-box`、`.diff-spin` 样式，以及 `.diff-btn` 基础样式。
- `sw.js`：`v18 → v19`（loader.js / app.js / diff.css / index.html 已在 LOCAL_ASSETS）。

### 验证
本地 `python http.server 8877` + `agent-browser`：

- 3000 行文档、500 处变更：首次点击对比到结果渲染完成 **344ms**，变更高亮与右侧标记条均正常。
- 4000 行文档、571 处变更：约 **404ms** 出结果。
- 右侧操作栏 WCO 让位仍保持：`.diff-bar::after` 占位、左侧/右侧面板对齐位置不变、仅最右侧按钮让位。

## manifest / 文件打开相关调整（用户多项诉求）
1. **manifest 取消 .bat 文件关联**：删除 `file_handlers` 中的 `"text/x-bat": [".bat",".cmd"]` 条目（v20 已 bump）。
2. **文件选择器放开为全部文件**：`js/files.js` 的 `pickerTypes()` 改为单个 `{description:'所有文件', accept:{'*/*':[]}}`，不再限制三类；`<input id=filePicker>` 加 `accept="*/*"`。
3. **打开前判文本/二进制**：`app.js openOne.doRead` 不再依赖「自动检测」开关，始终用 `Encoding.isBinary(bytes)` 判二进制；是二进制则弹确认框，确认后才以文本加载（`finish` 的 `binary` 标志经参数传入，避免作用域错位）。
4. **标签栏横向滚动条**：`css/app.css` 的 `.tab` 加 `flex:0 0 auto`（防被压缩），`.tabs` 改为可见细滚动条（`scrollbar-width:thin` + `::-webkit-scrollbar{height:8px}`，去掉原先 `none/height:0` 隐藏）。
5. **修复 PWA 文件关联概率空白**：
   - `files.js setupLaunchQueue` 的 `hasFiles` 判定由 `'files' in LaunchParams.prototype` 改为直接 `!!(params.files && params.files.length)`（原型探测在个别浏览器为 false 会把文件误判为快捷方式）。
   - `app.js registerServiceWorker` 的 `SW_UPDATED` 自动 reload 改为**非破坏性**：已打开文件 / 正在打开(launchBusy) / 有待处理(pendingLaunch) 时只弹「立即刷新」提示，不强制刷新，避免把 launchQueue 投递的文件冲掉（这正是「概率装好 PWA 后打开文件却空页面」的根因：新版本上线后首次拉起触发 SW 升级→旧逻辑随即 reload，而 launchQueue 只投递一次）。
   - `sw.js`：`v19 → v20`。
- 验证：node --check 全部通过；manifest JSON 校验通过且 bat 已从 handlers 移除。

## 修复 PWA WCO 下文本对比工具栏按钮无法点击
用户反馈：安装为 PWA 后，文本对比 appbar 中右侧操作栏和「交换两侧」「关闭」两个按钮无法点击。

### 根因
WCO（Window Controls Overlay）模式下，浏览器会把标题栏区域默认当作拖拽区（类似主编辑器 appbar 的 `-webkit-app-region: drag`）。diff-bar 里的按钮、下拉框没有显式声明 `-webkit-app-region: no-drag`，导致点击事件被系统拖拽逻辑吞掉，表现为按钮无法点击。

### 改动
- `css/diff.css` 在 WCO 专用规则末尾新增：
  - `:root.wco .diff-bar { -webkit-app-region: drag; }` —— 让 diff-bar 空白区可拖拽窗口；
  - `:root.wco .diff-side, :root.wco .diff-btn, :root.wco .diff-sel { -webkit-app-region: no-drag; }` —— 交互元素恢复点击。
- `sw.js`：`v22 → v23`（改了 CSS，必须 bump）。

### 验证
- `node --check js/app.js js/files.js sw.js` 通过。

## 修复 PWA WCO 下文本对比右侧操作栏与右侧文本框对齐
用户反馈：安装为 PWA 后，文本对比 appbar 中右侧操作栏（右侧（改）+ 打开文件 + 粘贴）没有与下方右侧 Monaco 编辑器文本框对齐，右侧留有空隙。

### 根因
原布局把「交换两侧」「关闭」两个全局按钮放在右侧操作栏之后、WCO 占位之前：
`[标题][左侧组][spacer][右侧组][spacer][交换][关闭][::after WCO占位]`
中间的 spacer 把右侧操作栏推离右边缘，导致它无法顶到 appbar 可用区域的右边界，视觉上与下方右侧编辑器错位。

### 改动
- `index.html`：把 `id="diffSwap"` 和 `id="diffClose"` 两个按钮移到右侧 `.diff-side` 内部，放到「粘贴」之后；删除右侧多余的 `.diff-spacer`。
- `css/diff.css`：
  - 新增 `.diff-side-right { margin-right: 14px; }`，让普通浏览器窗口下右侧操作栏右边缘与下方编辑器右侧的 `.diff-overview`（14px）对齐；
  - `:root.wco .diff-side-right { margin-right: 0; }` 覆盖，WCO 模式下由 `::after` 占位系统控件区域，不再额外留 14px。
- `sw.js`：`v23 → v24`（改了 HTML/CSS，必须 bump）。

### 验证
- `node --check js/app.js js/files.js sw.js` 通过；`index.html` 解析正常。
