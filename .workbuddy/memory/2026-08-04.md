## 修复文件选项卡把「新建标签页」按钮顶出窗口
- 现象：打开很多文件后，tabbar 右侧的「新建标签页」快捷按钮被挤出可视区。
- 根因：`.tabs` 是 flex 项且 `flex:1`，但缺少 `min-width:0`；其内部 `.tab` 是 `flex:0 0 auto`，于是 `.tabs` 的 min-content 等于所有标签宽度之和，flex 默认 `min-width:auto` 不让它收缩，`.tabs` 撑大把 `.tab-add` 顶出 tabbar。
- 修复（css/app.css）：
  - `.tabs` 改 `flex:1 1 0; min-width:0;` —— 让它可被压缩，内部 `overflow-x:auto` 才真正生效。
  - `.tab-add` 加 `flex:none;` —— 永远固定不收缩，留在 tabbar 最右。
  - 注：纵向滚轮转横向滚动的 `wheel` 监听（app.js ~L320）本来就存在，无需改动。
- 说明：主 appbar（新建/打开/保存等）与 tabbar 本就在 `.app` 网格的两条独立行（appbar-h / auto），互不绑定；本次问题仅发生在 tabbar 内部。
- sw.js VERSION v23 → v24（改了 CSS，按约定必须 bump，已装 PWA 才能拉新缓存）。
- 校验：`node --check` app.js/files.js/sw.js 全部通过。

## 二次修复：appbar 在 WCO/窄窗口下被挤出可视区
- 现象：用户反馈标签栏问题未修复，浏览器与 PWA 下顶部快捷按钮仍被顶出/截断。
- 复现：用本地测试页模拟多标签 + WCO 大让位后，appbar 的 `.appbar-actions` 因默认可收缩，被右侧 padding 推挤出可视区；普通浏览器若窗口缩窄同理。
- 修复（css/app.css）：
  - `.appbar` 加 `overflow:hidden` 防止内部溢出顶出。
  - `.appbar-lead` 改 `flex:1 1 0; min-width:0; overflow:hidden` —— 品牌区域可收缩截断。
  - `.appbar-brand` 加 `min-width:0; overflow:hidden`。
  - `.brand-name` 加 `overflow:hidden; text-overflow:ellipsis`，空间不足时截断显示。
  - `.brand-mark` 加 `flex:none`，Logo 不被压缩。
  - `.appbar-actions` 加 `flex:none`，快捷按钮区域整体固定不收缩。
- 保留：tabbar 内 `.tabs { flex:1 1 0; min-width:0; }` + `.tab-add { flex:none; }`，文件选项卡过多时仅选项卡横向滚动，新建按钮固定。

## 三次修复：appbar 仍被顶出 + PWA 下 + 按钮白色看不清
- 现象：用户继续反馈浏览器/PWA 全屏/普通窗口下，appbar 图标/按钮仍被顶出；PWA 下 tabbar 的「新建标签页」+ 按钮白色看不清。
- 根因（本轮真正元凶）：`.app` 的 grid 未显式声明列，默认 `1fr` 等价于 `minmax(auto, 1fr)`。当 appbar 内部（lead + actions）的 min-content 总宽超过容器时，整个 grid 列会基于内容撑开，导致 appbar 实际宽度远超视口/容器，右侧 actions 被溢出裁剪。此前只改 appbar 内部 flex 收缩是不够的。
- 修复（css/app.css）：
  - `.app` 显式声明 `grid-template-columns: minmax(0, 1fr);` 锁定列宽，防止基于子项 min-content 撑开。
  - `.appbar` 改回 `display: flex` 并加 `min-width: 0;`。
  - `.appbar-lead` 用 `flex: 1 1 auto; min-width: 0; overflow: hidden;`（之前 `flex:1 1 0` 收缩权重为 0 是错的）。
  - `.appbar-brand` 与 `.brand-name` 加 `flex: 1 1 auto; min-width: 0;` 确保可截断。
  - `.appbar-actions` 保持 `flex: none;` 固定不收缩，去掉 `margin-left: auto`（flex 剩余空间自然靠右）。
  - 限制 WCO 图标色只作用于 `.appbar .icon-btn`，避免把 tabbar 里的 `.tab-add` 也变成白色导致看不清。
- sw.js VERSION v25 → v26（改 CSS 必须 bump）。
- 校验：`node --check` app.js/files.js/sw.js 全部通过；agent-browser 本地测试页验证 600px/1264px 普通窗口、600px/500px WCO 亮色、600px WCO 暗色，appbar 按钮/图标均固定可见，+ 按钮颜色正常。

## 四次修复：恢复 appbar 左侧菜单/图标/标题
- 现象：用户反馈 PWA 和普通浏览器下，appbar 左侧的汉堡菜单、应用图标、"文本编辑器"标题丢失，只有右侧操作按钮。
- 根因：前一轮为了让右侧按钮不被挤出，把 `.appbar-lead` 设为 `flex: 1 1 auto; min-width: 0; overflow: hidden;`。在窄窗口或 WCO 右侧占位较大时，左侧作为可收缩区域被压缩到接近 0，`overflow: hidden` 把菜单/图标/标题全部裁剪掉。
- 修复（css/app.css）：
  - `.appbar-lead` 改为 `flex: 0 0 auto;` —— 左侧菜单+图标+标题整体固定，不再被右侧挤压。
  - `.appbar-brand` 加 `max-width: 220px; flex: 0 0 auto;` —— 标题过长时内部截断，但品牌区本身不收缩。
  - `.appbar-actions` 改为 `flex: 1 1 auto; min-width: 0; overflow: hidden;` —— 右侧操作按钮区占据剩余空间；空间不足时由右侧被裁剪，优先保证左侧可见。
  - 保留 `.appbar { overflow: hidden; min-width: 0; }` 与 `.app { grid-template-columns: minmax(0, 1fr); }`，继续防止 grid 列撑开。
- 说明：这是布局优先级的取舍 —— 左侧品牌/菜单必须始终可见，右侧按钮在极端窄窗口下可能部分被裁剪；已有的 `@media (max-width: 520px)` 会隐藏 #btnNew/#btnDownload 来缓解。
- sw.js VERSION v26 → v27（改 CSS 必须 bump）。
- 校验：`node --check` app.js/files.js/sw.js 全部通过；agent-browser 本地测试页验证 600px 容器 + 300px WCO 占位下，左侧完整显示；普通浏览器宽窗口下两侧均正常；WCO 暗色模式左侧也正常。
