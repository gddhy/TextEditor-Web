## 修复 PWA WCO 下 appbar 按钮完全消失
- 根因：WCO 的 `env(titlebar-area-width)` 是标题栏**可用区域**宽度（左侧可绘制内容宽度），不是右侧系统控件宽度。之前 CSS 和 JS 都把它当作系统控件宽度来用，导致 PWA 下 `padding-right` 几乎等于整个窗口宽度，把 `.appbar-actions` 全部挤出可视区。
- 正确公式：系统控件宽度 = `100vw - env(titlebar-area-x, 0px) - env(titlebar-area-width, 100vw)`；JS 中对应 `window.innerWidth - getTitlebarAreaRect().right`。
- 修改：
  - `css/app.css`：`.appbar` 的 `padding-right` 改为 `calc(100vw - env(titlebar-area-x, 0px) - env(titlebar-area-width, 100vw) + env(safe-area-inset-right, 0px))`。
  - `js/app.js`：`setupWindowControlsOverlay` 中 `--wco-right` 改为 `Math.max(0, Math.ceil(window.innerWidth - r.right))`。
  - `css/diff.css`：`.diff-bar::after` 的 env 回退也改为同样的正确公式。
- `sw.js`：VERSION v28 → v29。
- 校验：`node --check` app.js/files.js/sw.js 通过；本地测试页复现 bug（padding-right = 可用宽度 → actionsW=0）并验证修复后（padding-right = 系统控件宽度 → actionsW=580/按钮 40px 正常显示）。

## 修复首页启动概率卡在 CDN 检测（loader.js）
- 现象：概率一直卡在「正在探测/加载编辑器」无法进入编辑器，刷新网页即正常。
- 根因（`js/loader.js` 旧实现）：
  1. `probeFastest` 解析后 resolve 的是 `res.url`（最终 URL）；npmmirror 等 CDN 会 302 重定向（registry.npmmirror.com → cdn.npmmirror.com），导致返回的 base 与原 `Config.orderedMirrors()` 中任一 `mirror.base` 都不匹配，`hit` 为 undefined、reorder 失效，探针选中的最快源被白白浪费。
  2. 无 `preferredMirror` 快速路径：冷启动每次都走并发探测 + 串行降级，且串行遍历全部源（13 个），单源超时很长，叠加上述浪费 → 长时间挂起。
- 修复：
  1. `probeFastest` 改为 resolve **命中的 mirror 对象**（而非最终 URL），保证 302 重定向后 base 仍正确、探针结果被真正采纳。
  2. `loadMonaco` 新增 preferredMirror 优先直连路径：本地已记录上次成功源时直接尝试它；失败才退回探测+降级（这也解释了「刷新就能进」——preferredMirror 已存好源）。
  3. `loadMonacoFrom` 缩短超时：`loader.js` 加载 12000ms、editor.main 20000ms；串行降级仅取前 6 个源封顶总时间。
  4. `probeFastest` 命中后**不再 await res.text()**（某些 CDN 响应体流会停滞导致永久挂起），仅确认可达即可，真正下载交给 loadMonacoFrom。
- 校验（无需联网，避免浏览器自动化 429 限流）：
  - `node --check loader.js` 通过。
  - 注入式 Node 逻辑测试：mock `fetch` 模拟 npmmirror 302 重定向到 cdn.npmmirror.com，`probeFastest` 仍返回 base=`registry.npmmirror.com/...` 的原始 mirror 对象（PASS）；全部源失败时 1ms 内 reject（PASS）。
- SW：`sw.js` VERSION v36 → v37（loader.js 改动且位于 LOCAL_ASSETS 预缓存列表，必须 bump 让已装 PWA 重新拉取）。
- 清理：删除验证用的 `test-loader.html`、`_probe_test.js`。
