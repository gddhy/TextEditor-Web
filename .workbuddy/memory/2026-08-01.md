# 2026-08-01

## Text Studio - Web 文本编辑器（PWA）

基于 Monaco Editor 0.53.0 构建了完整的 Web 端文本编辑器。

### 核心特性
- Material Design 3 界面（亮色/暗色/跟随系统）
- 多编码支持：UTF-8/UTF-16/GBK/GB18030/Big5/Shift_JIS/EUC-KR/ISO-8859/Windows-* 等 20+ 种
  - **关键实现**：浏览器原生只支持 UTF-8 编码，GBK/Big5/Shift_JIS 等编码通过反查 TextDecoder 动态构建「字符→字节」映射表实现
- Markdown 预览（内置解析器 + marked 增强 + DOMPurify 消毒 + Monaco colorize 代码高亮）
- PWA：launch_handler navigate-new + file_handlers 注册 56 种文本扩展名
- File System Access API：覆写保存到原文件（不支持时回退到下载）
- LaunchQueue 接收 PWA 文件关联启动
- 多标签页 + 会话恢复 + 文件拖放

### CDN 多源策略
- Monaco 镜像源 12 个（npmmirror/bootcdn/staticfile/字节/jsdelivr 等）
- 并发探测最快源 → 失败串行降级（loader.js）
- 切镜像时清理 AMD 全局状态

### 文件结构
```

  index.html              - 主页面
  manifest.webmanifest    - PWA 配置
  sw.js                   - Service Worker（cache-first 本地 + SWR CDN）

  js/config.js            - CDN 配置 + 设置持久化
  js/loader.js            - 多镜像加载器
  js/encoding.js          - 编码检测/解码/编码
  js/langs.js             - 扩展名→Monaco 语言映射
  js/markdown.js          - Markdown 渲染
  js/ui.js                - UI 组件（菜单/对话框/snackbar）
  js/files.js             - 文件读写（FS Access API + LaunchQueue + 下载）
  js/editor.js            - Monaco 封装
  js/app.js               - 主控制器
  icons/                  - PWA 图标（64/192/256/512 + maskable）
  tools/gen-icons.js      - 纯 Node PNG 生成器
```

### 验证结果（localhost:8788 + agent-browser）
- Monaco 加载成功（来源：npmmirror 阿里云）
- 亮色/暗色主题切换正常
- Markdown 预览渲染（标题/表格/代码/列表）
- 主菜单、设置对话框、编码选择对话框全部正常
- GBK/Shift_JIS/Big5 编码测试全部 0 丢失

### 已知限制
- File System Access API 仅 Chromium 桌面浏览器支持，其他浏览器自动回退到下载
- PWA 文件关联需要 HTTPS 或 localhost
- 内置 Markdown 解析器对复杂嵌套嵌套嵌套结构的支持不如 marked，但 marked CDN 加载失败时仍可工作

### 关键陷阱
- **Service Worker 缓存**：调试时若改了 JS 必须 bump `sw.js` 的 VERSION 并 unregister SW，否则浏览器跑旧代码
- **agent-browser 在 localhost 卡死但 127.0.0.1 正常**：可能与 Chrome profile/profile lock 有关，遇到挂起换 127.0.0.1
- **showSaveFilePicker 拒绝 `.*`**：必须是 `^\.[a-zA-Z0-9]+$` 格式的扩展名
- **Ed.createDoc 不触发 `onDidChangeContent`**：初始化内容不会启动 `scheduleSession`，想立即持久化要手动 `applyEdits` 或直接调 `Files.putDocs`
- **restoreFromSnaps 脏标记丢失**：createDoc 默认 `dirty:false`，需显式 `doc.dirty = true` 还原未保存状态
- **browsers list**：`bsk browsers` 返回 `INSTANCE BROWSER EXT LABEL SESSIONS`；session start 报 "no browser connected" 时可能是连接刚建立但 daemon 还没同步，等几秒重试或显式传 `--browser <INSTANCE>`

### 第七轮改动（2026-08-01 深夜 · 本地文件外部变动监听）
用户问：网页内通过「选择文件打开/LaunchQueue 打开」拿到的本地文件，能否监听磁盘外部修改并提示「重新加载 / 保存我的 / 另存为」？答：能实现，做了。

**方案（混合）**：
- 新建 `js/watch.js` —— 本地文件外部变动监听模块，与 UI 解耦，通过 `onChanged` / `onMissing` 回调通知上层。
- 两条路结合：① `FileSystemObserver`（Chrome 129 起实验性 origin trial，能用时作「即时催促」）；② 轮询 `handle.getFile()` 比对 `{lastModified, size}` 签名作真实判定（通用可靠兜底）。
- 常量：`MIN_INTERVAL=1000`、`QUIET_AFTER_PROMPT=3000`（提示后静默避免连续改动刷屏）、`MISS_CONFIRM=2`（连续 N 次读不到才报「文件消失」，防「写临时→删原→改名」原子保存误报）。
- 判定逻辑 `checkDoc`：权限只查不要（`queryPermission` 不弹框，无权返回 null 静默跳过，OPFS 句柄无权限模型直接走 `getFile`）；首查只登记基线 `doc.fsSig`，之后签名变化 → `notify('onChanged')`；`NotFoundError`/`NotReadableError` 累计到 `MISS_CONFIRM` → `notify('onMissing')`。
- `tick()` 后台不轮询（`document.hidden` 跳过）；`visibilitychange`+`focus` 唤醒即查（用户最常见场景：切到别的程序改了文件再切回）。
- 基线登记 `baseline(doc, file)` 在打开/保存/重载后调用，避免把自己写入当成外部改动；`forget(doc)` 关文档时清空 `fs*` 字段。

**UI 集成（`js/app.js`）**：
- `watchEnabled()` = `Watch.supported && Cfg.get('watchFiles')`；`startWatch()` 接管启停，docs 取 `Ed.docs`。
- 三类提示：
  - 干净文档 → snack「「name」已被其它程序修改」+ 动作「重新加载」（8 秒，可启用 `watchAutoReload` 自动重载走 snack 成功）。
  - 脏文档 → `UI.confirm` 4 按钮冲突框（忽略 / 查看差异 / 重新加载 / 保存我的），走差异时调 `openDiff` + `setDiffSide('left', 磁盘版本)` + `setDiffSide('right', 编辑器内容)` + `#diffRightSel=doc.id`。
  - 文件消失 → `Ed.markDirty(doc)` + `doc.handle=null` + `Watch.forget(doc)` + snack「「name」在磁盘上已不存在…」+ 动作「另存为」。
- `reloadFromDisk`：用 `Files.readBytes` + `Encoding.decode` + **`model.pushEditOperations`**（非 `setValue`，支持 Ctrl+Z 撤回）；更新 `bom/eol/size` → `Ed.markSaved` + `markFsBaseline` + 刷新预览 + `scheduleSession`。
- 「从磁盘重新加载」菜单（`data-act="reloadDisk"`）：脏时先 confirm「放弃未保存更改？」，菜单点击是用户手势故可用 `Files.verifyPermission(handle, false)` 弹权限框。

**设置 & 资源注册**：
- `js/config.js` `DEFAULTS` 新增 `watchFiles:true` / `watchAutoReload:false` / `watchInterval:3000`。
- `index.html` 设置区加 `#setWatchFiles` + `#setWatchAutoReload`（后者带 `#setWatchHint` 动态提示支持度）；菜单「打开文件夹」后加「从磁盘重新加载」；在 `files.js` 与 `editor.js` 之间插入 `<script src="./js/watch.js"></script>`。

**坑 / 经验**：
- `Cfg` 是 `app.js` IIFE 内的闭包局部变量（`var Cfg = Config`），**不会挂在 `window` 上**，`window.Cfg` 是 `undefined`；探测 `Cfg.get('watchFiles')` 必须经 App 导出或从 Watch 间接验证运行态。本轮就是通过 `Watch.isRunning()` + 实际 snack 触发反证配置默认生效。
- **agent-browser eval 会被「挂起的 promise」卡死**：脏路径 `onFileChanged` 走 `UI.confirm` 返回「等用户点按钮」的 promise，`await Watch.check(doc)` 永不 resolve → CDP 抛 `Promise was collected`。**修复**：用 `window.Watch.check(doc)` 触发但不 await（fire-and-forget），再 `await new Promise(r=>setTimeout(r, 60))` 刷一帧微任务让 `showModal()` 完成，最后读 DOM 返回 JSON。
- OPFS `removeEntry` 后用旧 `FileSystemFileHandle.getFile()` 不一定抛 `NotFoundError`（行为不稳定），不能直接依赖；要用假 handle 始终 reject 验证 MISS_CONFIRM。
- 首次 `Watch.check(doc)` 若 `doc.fsSig` 未登记，只会登记不通知——必须先 `Watch.baseline(doc, file)`。
- 自身保存后必须 `markFsBaseline`（或 `Watch.baseline`），否则下次轮询会把自己刚写入当外部改动（`notify` 后虽会自动接受当前签名，但 baseline 更干净）。
- **关键 bug 防御**：`<dialog>.showModal()` 是同步打开，但后续 read 操作必须放在微任务之后（`setTimeout(0)` 或 `await Promise.resolve()`），否则 DOM 还没插入就查不到。
