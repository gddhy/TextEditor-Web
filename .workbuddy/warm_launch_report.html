PWA 快捷方式 warm launch 修复 · 验证报告

文本编辑器 · C:\APP\web-editor · 2026-08-02

任务

窗口已存在时（focus-existing 复用窗口），点击 PWA 快捷方式 ?action=new 与 ?action=new&ext=md 此前无效，需修复。 manifest 的 focus-existing 参数严格保持不动。

根因

  • 冷启动：页面被导航到快捷方式 URL，bootstrapInitialDoc() 读 location.search 即可创建文档。
  • warm launch（窗口已存在）：页面不会重新导航，浏览器通过 launchQueue.setConsumer 把 params.targetURL 投递到已运行的页面（params.files 为空）。
  • 原代码只处理 params.files，把 targetURL 丢弃 → 静默失效。

改动

  • js/files.js：setupLaunchQueue(onFiles, onTargetUrl) 在「无 files + 有 targetURL」时回调 onTargetUrl(url)。
  • js/app.js：新增 handleShortcutUrl(url)（解析 targetURL query → runShortcutFromSearch），抽出共用的 runShortcutFromSearch(search)，bootstrapInitialDoc() 增加 state.pendingShortcut 分支，state 加 pendingShortcut:null。
  • manifest.json：launch_handler.client_mode 仍为 focus-existing（未改动）。shortcuts 名称/URL 保持「新建文档」「新建 Markdown 文档」。
  • sw.js：text-editor-v9 → v10（确保已装 PWA 拉到新 app.js）。

验证结果（从真实源码抽取函数做受控单测）

场景期望结果
?action=new&ext=md（warm）新建 未命名-1.md + 预览开启 + 激活OK
?action=new（warm）新建 未命名-1.txt、预览关闭OK
连续两次 &ext=md未命名-1.md + 未命名-2.md（不复用）OK
action=open（非 new）不新建任何文档OK
files.js 接线仅 targetURL 时回调 onTargetUrl；带 files 时不误触OK

说明：实机浏览器验证因测试环境 copilot.tencent.com 解析失败（瞬态 502）受阻，故采用「抽取 app.js / files.js 真实函数源码 + 受控沙箱」的方式验证核心逻辑全链路，覆盖上述场景。

手动验证步骤（建议）

  1. 以 localhost 或 HTTPS 访问并安装为 PWA。
  2. 首次（窗口不存在）点击右键任务栏图标 →「新建 Markdown 文档」：应新建 未命名-1.md 并展开预览。
  3. 保持窗口打开，再次从系统快捷方式点击同一项：应再新建一个文档（不再静默无反应）。
